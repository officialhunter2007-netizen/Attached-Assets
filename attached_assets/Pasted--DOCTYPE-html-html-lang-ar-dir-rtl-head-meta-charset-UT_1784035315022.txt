    <h3>① رسالة التفاوض (NEGOTIATE_MESSAGE)</h3>
    <p>
      أحمد يكتب اسمه وكلمة مروره. الحاسوب يرسل للخادم رسالة أولى تقول:
      "مرحباً، أنا عميل، أريد الدخول، اسمي أحمد، وهذه هي الميزات التي أدعمها (NTLMv1 أو v2، اللغة، إلخ)."
    </p>
    <div class="codebox">
<span class="comment"># ما تحتويه رسالة التفاوض</span>
- Signature: "NTLMSSP\0"  <span class="comment"># توقيع ثابت للتعريف بالبروتوكول</span>
- MessageType: 1           <span class="comment"># نوع الرسالة (1 = Negotiate)</span>
- NegotiateFlags: ...      <span class="comment"># ما الخصائص المدعومة</span>
- DomainName: "COMPANY"    <span class="comment"># اسم الشركة / النطاق</span>
- Workstation: "AHMED-PC"  <span class="comment"># اسم جهاز أحمد</span>
    </div>

    <h3>② رسالة التحدي (CHALLENGE_MESSAGE)</h3>
    <p>
      الخادم يستقبل الطلب ويولّد رقماً عشوائياً كبيراً (8 بايت = 64 بت) يسمى الـ <strong>Server Challenge</strong>. يرسله لأحمد.
    </p>
    <div class="highlight">
      🎲 <strong>لماذا عشوائي؟</strong> لأن لو كان ثابتاً، يستطيع المهاجم التقاط جواب قديم وإعادة إرساله (Replay Attack). الرقم العشوائي يضمن أن كل جلسة فريدة.
    </div>
    <div class="codebox">
<span class="comment"># رسالة التحدي</span>
- MessageType: 2
- ServerChallenge: A3F2B7C9D4E10A5B  <span class="comment"># الرقم العشوائي</span>
- TargetName: "COMPANY"
- NegotiateFlags: ...
    </div>

    <h3>③ أحمد يحسب الجواب</h3>
    <p>الحاسوب يأخذ NT Hash لكلمة مرور أحمد ويستخدمه مع الـ Challenge لحساب الـ Response.</p>
    <div class="codebox">
<span class="comment"># في NTLMv1 (مبسّط)</span>
NT_Hash = <span class="val">MD4("Ahmed2024!" بترميز Unicode)</span>
<span class="comment"># = 8846F7EAEE8FB117AD06BDD830B7586C</span>

<span class="comment"># يُوسَّع الـ Hash من 16 بايت إلى 21 بايت بإضافة أصفار</span>
NT_Hash_Extended = NT_Hash + 00 00 00 00 00

<span class="comment"># ينقسم إلى 3 أجزاء × 7 بايت</span>
<span class="comment"># كل جزء يُشفَّر بخوارزمية DES مع الـ Challenge</span>

Response = DES(K1, Challenge) + DES(K2, Challenge) + DES(K3, Challenge)
<span class="comment"># الناتج: 24 بايت → هذا هو الـ NT Response</span>
    </div>

    <h3>④ رسالة المصادقة (AUTHENTICATE_MESSAGE)</h3>
    <p>أحمد يرسل للخادم: اسمه المستخدم + اسم النطاق + اسم الجهاز + الـ NT Response.</p>
    <div class="highlight">
      🔐 <strong>لاحظ:</strong> كلمة المرور نفسها <em>لا تُرسَل أبداً</em> — فقط الـ Response المحسوب منها.
    </div>

    <h3>⑤-⑥ الخادم يتحقق عبر الـ DC</h3>
    <p>
      الخادم يرسل للـ DC: [اسم المستخدم + Server Challenge + NT Response].
      الـ DC يفعل نفس الحساب: يسحب NT Hash أحمد من قاعدة بياناته، يحسب الجواب المتوقع،
      يقارنه بما أرسله الخادم.
    </p>
    <div class="codebox">
<span class="comment"># الـ DC يحسب</span>
Expected_Response = DES(K1, ServerChallenge) + DES(K2, ...) + DES(K3, ...)

if Expected_Response == Received_Response:
    return <span class="val">"ACCESS_GRANTED"</span>  <span class="comment"># ✅ صح!</span>
else:
    return <span class="key">"ACCESS_DENIED"</span>   <span class="comment"># ❌ خطأ</span>
    </div>

    <h3>⑦-⑧ النتيجة النهائية</h3>
    <p>
      الـ DC يرسل قراره للخادم عبر بروتوكول يسمى <strong>NetLogon</strong>. 
      الخادم يبلّغ أحمد بالنتيجة.
    </p>
  </div>

  <div class="card">
    <h2><span class="icon-lg">🆕</span> ما الجديد في NTLMv2 بالتفصيل؟</h2>

    <h3>١. إضافة Client Challenge (Blob)</h3>
    <p>
      في v1، فقط الخادم يولّد الـ Challenge. في v2، العميل أيضاً يولّد رقماً عشوائياً خاصاً به (يسمى Client Challenge أو Blob).
      الجواب النهائي يعتمد على <strong>كليهما معاً</strong>.
    </p>
    <div class="highlight">
      🔒 <strong>لماذا مهم؟</strong> حتى لو تمكّن مهاجم من التحكم بالـ Server Challenge، لا يستطيع التنبؤ بالجواب الصحيح لأن الـ Client Challenge عشوائي أيضاً.
    </div>

    <h3>٢. إضافة الطابع الزمني (Timestamp)</h3>
    <p>
      الـ Blob يحتوي على وقت دقيق. الخادم والـ DC يتحققان أن الجواب "جديد". 
      لو المهاجم التقط جواباً قديماً وحاول إعادة إرساله بعد 5 دقائق — سيُرفض.
    </p>

    <h3>٣. خوارزمية HMAC-MD5 بدل DES</h3>
    <div class="codebox">
<span class="comment"># NTLMv1 Response (بسيط وضعيف)</span>
v1_Response = DES(NT_Hash, ServerChallenge)

<span class="comment"># NTLMv2 Response (أقوى)</span>
NT_Hash_v2 = HMAC_MD5(NT_Hash, Username + Domain)
v2_Response = HMAC_MD5(NT_Hash_v2, ServerChallenge + Blob)
<span class="comment"># الـ Blob يحتوي: Timestamp + ClientChallenge + TargetInfo</span>
    </div>

    <h3>٤. Target Information (TargetInfo)</h3>
    <p>
      الـ Blob في v2 يحتوي أيضاً على معلومات النطاق والخادم المستهدف.
      هذا يمنع هجوم يسمى <strong>Relay Attack</strong> (سنشرحه) — لأن الجواب مرتبط بخادم معين.
    </p>
  </div>

      <p>

        إذا سرق المهاجم الـ NT Hash من ملف SAM أو NTDS.dit،

      </p>

      </p>
    </div>

    <div class="attack-card">
      <h4>🔁 هجوم Replay Attack</h4>

      </p>
    </div>

      </p>
